# Mini NPU 시뮬레이터 (Codyssey E1-3)

패턴(n×n 숫자 행렬)과 필터를 같은 위치끼리 곱해서 모두 더하는 **MAC(Multiply-Accumulate) 연산**으로
패턴이 십자가(Cross)인지 X인지 판정하는 Python 콘솔 프로그램입니다.
MAC은 AI 모델이 이미지를 처리할 때 수억 번 반복하는 기본 연산이고, NPU는 이 단순 반복 연산을
병렬로 처리하기 위해 만든 AI 전용 칩입니다. 이 프로그램은 그 원리를 반복문으로 직접 구현해 봅니다.

## 실행 방법

```bash
cd mission03          # main.py와 data.json이 있는 폴더에서 실행
python3 main.py       # Windows: python main.py
```

- 실행하면 모드를 고릅니다.
  - `1`: 3x3 필터 A·B와 패턴을 키보드로 한 줄씩(공백 구분) 입력
  - `2`: `data.json`의 필터(5x5, 13x13, 25x25)와 패턴을 읽어 일괄 판정
- `data.json`은 `main.py`와 같은 폴더에 있어야 합니다 (상대 경로 `data.json`으로 읽음).
- 환경: Python 3.8 이상, 표준 라이브러리(json, math, time)만 사용. 외부 라이브러리 없음.

## 구현 요약

### 데이터 구조
- 행렬은 2차원 list(`list` 안에 `list`)로 저장합니다. `matrix[i][j]`가 i행 j열 값입니다.
- 크기는 `len(pattern)`으로 알아내므로 3x3부터 25x25까지 같은 함수로 처리합니다.

### 모드 1 입력 검증 (`read_matrix`)
- `while len(matrix) < n` 반복으로 **성공한 줄 수**가 n이 될 때까지 받습니다. 틀린 줄은 그 줄만 다시 받습니다.
- 한 줄 검사 순서: ① 숫자 개수가 n개인가(`split()` 결과 길이, if) → ② 모두 숫자인가(`float()`, try/except ValueError) → ③ nan·inf가 아닌가(`math.isfinite`, if)

### MAC 연산 (`mac`)
- 이중 for문으로 모든 칸을 방문하며 `total += pattern[i][j] * filter[i][j]`를 누적합니다.
- `total = 0.0`에서 시작해 항상 float 점수를 반환합니다. NumPy 등은 쓰지 않습니다.

### 동점 처리 정책 (`judge`, epsilon)
- `abs(score_a - score_b) < 1e-9`이면 동점으로 보고 `UNDECIDED`(모드 1 화면은 "판정 불가")를 반환합니다.
- 동점 검사를 가장 먼저 합니다. `>` 비교를 먼저 하면 오차 수준의 차이(예: 0.30000000000000004 > 0.3)로 한쪽이 이겨 버립니다.
- 이유: float는 2진수 근사값이라 `0.1 + 0.2 == 0.3`이 False입니다. 수학적으로 같은 두 점수가 미세하게 갈릴 수 있습니다.

### 라벨 정규화 (`normalize_label`)
- 데이터마다 표기가 다릅니다: 정답(expected)은 `+` / `x`, 필터 키는 `cross` / `x`.
- 번역표 `LABEL_MAP = {"+": "Cross", "cross": "Cross", "x": "X"}`로 내부 표준 라벨 **Cross / X**로 통일합니다.
  `.strip().lower()` 후 찾으므로 `" X "`, `"CROSS"`도 처리됩니다. 표에 없으면 `None`.
- 출력과 PASS/FAIL 비교는 모두 표준 라벨 기준입니다. 정규화가 없으면 `"X" == "x"`처럼 같은 뜻인데도
  에러 없이 전부 FAIL이 됩니다.

### 모드 2 검사 순서 (케이스 단위 FAIL)
케이스마다 아래 관문을 차례로 통과해야 판정합니다. 하나라도 걸리면 사유를 기록하고 다음 케이스로 넘어갑니다(`continue`).
프로그램은 중단되지 않습니다.

1. 케이스가 dict인가
2. 키 `size_{N}_{idx}`에서 N 추출 (`int(key.split("_")[1])`, 실패 시 IndexError/ValueError)
3. `size_{N}` 필터가 있는가
4. 필터 키 정규화 (`cross` → `Cross`, `x` → `X`)
5. 패턴과 두 필터가 모두 N×N인가 (`is_square_matrix`)
6. expected 라벨이 정규화되는가
7. MAC 계산 (행렬에 문자열 → TypeError, 점수가 nan/inf → FAIL)
8. `judge` 결과 A/B를 Cross/X로 바꿔 expected와 비교 → PASS / FAIL

파일 자체 오류(파일 없음, JSON 형식 깨짐, 최상위에 patterns 없음)는 안내 후 모드 2를 종료합니다.

### 성능 측정 (`measure_mac_time`)
- `time.perf_counter()`로 MAC 함수 호출만 10회 반복한 시간을 재고 1회 평균(ms)을 냅니다.
  측정 구간에 입력·출력·파일 읽기는 없습니다.
- 크기별 측정용 행렬(값 1.0)을 만들어 3x3, 5x5, 13x13, 25x25를 측정합니다 (계산 시간은 값과 무관).

## 결과 리포트

### 1. 실패 원인 분석 (6개 중 3개 FAIL)

실패 원인을 "데이터/스키마 vs 로직 vs 수치 비교" 세 가지로 나눠 확인했습니다.

- **데이터/스키마 문제가 아님**: 6개 케이스 모두 키 형식(`size_N_idx`)이 맞고, 패턴·필터 크기가 일치합니다.
  패턴을 그림으로 출력해 보면 expected 라벨(x → X 모양, + → 십자가 모양)과 실제 모양도 모두 일치합니다.
- **로직 문제가 아님**: 같은 코드로 나머지 3개는 PASS했고, "판정은 했는데 정답과 다른" FAIL은 0개입니다.
- **수치 비교 문제**: FAIL 3개(size_5_1, size_13_2, size_25_1)는 모두 UNDECIDED입니다.
  세 케이스를 소수 오차가 없는 분수(`fractions`)로 다시 계산하면 두 점수가 **수학적으로 정확히 같습니다**
  (9/10 = 9/10, 15/2 = 15/2, 49/10 = 49/10).
- 동점이 생긴 이유는 필터 가중치입니다. 예를 들어 size_5의 X 패턴은 Cross 필터와 가운데 한 칸(값 0.9)만 겹쳐 0.9,
  X 필터와는 9칸이 모두 겹치지만 각 칸이 0.1이라 0.1 × 9 = 0.9가 됩니다.
  MAC 점수는 "모양이 겹치는 정도"가 아니라 "가중치를 곱한 합"이라서, 가중치가 고르지 않으면 모양이 완벽히 맞아도 구분되지 않습니다.
- float 연산 오차가 이 동점을 미세하게 갈라 놓았습니다(0.9 vs 0.8999999999999999). epsilon 없이 `>`로만 비교하면
  세 케이스 모두 **expected와 반대 라벨**로 판정됩니다. epsilon 정책은 이것을 "근거 없는 오답" 대신 "판정 불가"로 처리합니다.
- 따라서 이 3개 FAIL은 코드 결함이 아니라 데이터에 설계된 동점 케이스이고, 비교 정책이 의도대로 동작한 결과입니다.
  PASS로 만들려면 코드가 아니라 필터 가중치를 바꾸거나 동점 시 처리 규칙(예: 정답 쪽 우선)을 새로 정해야 합니다.

### 2. 성능 표 해석과 시간 복잡도 O(N²)

- `mac`은 이중 for문으로 N×N개의 칸을 한 번씩 방문하며 곱셈 1번 + 덧셈 1번을 합니다. 그래서 연산 횟수는 정확히 N²입니다.
- 측정 결과도 N²을 따라 늘어납니다. 13x13 → 25x25에서 연산 횟수는 169 → 625(약 3.7배), 평균 시간은 0.0114 → 0.0393ms(약 3.4배)입니다.
  5x5 → 25x25에서도 연산 횟수 25배, 시간 약 16배로 같은 방향입니다.
- 작은 크기(3x3, 5x5)에서 비율이 덜 맞는 것은 함수 호출, 반복문 준비 같은 고정 비용이 상대적으로 크기 때문입니다.
  크기가 커질수록 고정 비용 비중이 줄어 N²에 가까워집니다.
- 따라서 시간 복잡도는 **O(N²)**입니다. 한 변의 길이가 2배가 되면 연산량과 시간은 약 4배가 됩니다.
  실제 AI 모델은 훨씬 큰 필터를 수천 개 쓰기 때문에 이 반복 연산을 병렬로 처리하는 NPU가 필요합니다.
